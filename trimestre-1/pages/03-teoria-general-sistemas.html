Teoría General de Sistemas

La TGS es el estudio interdisciplinario de los sistemas en general. Analiza principios comunes en sistemas biológicos, sociales y tecnológicos, permitiendo entender cómo los elementos interactúan para lograr un objetivo. Es la base conceptual para el análisis, diseño y construcción de software.

01 / APRENDIZAJE

Resultados de aprendizaje

Los resultados de aprendizaje (RAP) establecidos para esta competencia son:

1. Caracterizar procesos

Caracterizar los procesos de la organización de acuerdo con el software a construir.

2. Recolectar información

Recolectar información del software a construir de acuerdo con las necesidades del cliente.

3. Establecer requisitos

Establecer los requisitos del software de acuerdo con la información recolectada.

02 / CONCEPTO

¿Qué es la teoría general de sistemas?

  • Estudio interdisciplinario de los sistemas en general.
  • Analiza principios comunes en diferentes tipos de sistemas (biológicos, sociales, tecnológicos, etc.).
  • Permite entender cómo los elementos de un sistema interactúan para lograr un objetivo.
  • Un módulo sirve para entender otro módulo. Entender cómo funciona cada elemento en un sistema es fundamental para comprender su funcionamiento global.
03 / HISTORIA

Origen

  • Nació en la biología y se expandió a otras disciplinas.
  • No resuelve problemas específicos, sino que crea marcos teóricos útiles.
  • Se desarrolló como respuesta a las limitaciones de la ciencia clásica en el estudio de sistemas vivos y abiertos.
Padre de la TGS: Ludwig von Bertalanffy (1950–1968), biólogo alemán.
04 / EXPANSIÓN

Desarrollo y expansión

Aunque la TGS surgió en el campo de la biología, pronto se vio su capacidad de inspirar desarrollos en disciplinas distintas y se apreció su influencia en la aparición de otras nuevas. A partir de entonces se ha ido constituyendo el amplio campo de la sistémica o de las ciencias de los sistemas.

Especialidad Descripción
CibernéticaEstudio de los sistemas de control y comunicación.
Teoría del caosComportamiento impredecible en sistemas deterministas.
Teoría de juegosAnálisis de decisiones estratégicas entre agentes.
Teoría de la informaciónTransmisión y procesamiento de información.
Teoría de las catástrofesCambios abruptos en sistemas dinámicos.
05 / DEFINICIÓN

¿Qué es un sistema?

Sistema: Conjunto de elementos relacionados y coordinados para un fin.

Los sistemas incluyen una estructura y una funcionalidad. Todo sistema contiene subsistemas.

Ejemplo: en un salón de clase, cada aprendiz aprende en un subsistema, el cual está sostenido por el sistema general (ambiente, TICs, instructor y aprendices), que a su vez forma parte de otro sistema mayor.

Todo sistema tiene

Input (Entrada)

Información, energía o materia externa.

Procesador

Transforma las entradas en salidas (throughput).

Output (Salida)

Resultados del sistema.

Feedback

Salidas que se reintegran como entradas para mejorar el sistema.

Variedad de sistemas

Tipo de sistema Ejemplos
Sistemas naturalesCuerpo humano, sistema solar
Sistemas artificialesComputadora, red eléctrica
Sistemas abstractosMatemática, sistema legal
06 / CLASIFICACIÓN

Tipos de sistemas

Tipo Descripción
Sistemas abiertos Intercambian información con el entorno (ej. una empresa).
Sistemas cerrados No intercambian información (ideal teórico, no existe en la realidad).
Semiabiertos / semicerrados Intercambio limitado (ej. sistemas técnicos con firewall).
07 / PROPIEDADES

Propiedades clave

Entropía

Grado de desorden en el sistema. Ejemplo: fallos en una red informática.

Homeostasis

Equilibrio interno autorregulado. Ejemplo: termostato ajustando temperatura.

Sinergia

Las partes colaboran para un resultado mayor. Ejemplo: equipo de trabajo eficiente.

Adaptabilidad

Capacidad de ajuste a cambios externos. Ejemplo: empresas que innovan (Netflix).

08 / ENFOQUE

Enfoque sistémico

El enfoque sistémico es la forma de analizar la realidad como un conjunto interconectado de elementos, donde cada parte influye en el todo y viceversa, priorizando las relaciones sobre las entidades individuales.

Características

  • Estructural: identifica componentes y relaciones (ej. diagramas).
  • Integral: evalúa rendimiento, entropía y efectividad.

Aplicación en organizaciones inteligentes

El enfoque sistémico permite analizar todas las razones que influyen en una situación. Un solo factor puede cambiar todo un sistema.

Ejemplo: si una empresa empieza a tener pérdidas, se deben evaluar múltiples factores: ¿tiene demasiado o poco personal?, ¿hay mucho inventario?, ¿los procesos son eficientes?

Premisas del enfoque sistémico

  • Los sistemas son abiertos.
  • Su función depende de su estructura.
09 / DATOS

Datos e información

Datos

Los datos son un conjunto de información desorganizada, obtenida a partir de entrevistas, experimentos y otras formas de levantamiento de información.

Métodos de recolección de datos

Encuestas

Cuestionarios y formularios estructurados.

Entrevistas

Conversaciones dirigidas con stakeholders.

Observación

Observación directa del entorno.

Documentos

Registros y experimentos previos.

Tipos de datos

Tipo Descripción Ejemplo
Cualitativos Describen cualidades o características. Colores, opiniones.
Cuantitativos Se expresan en números. Edades, temperaturas, fechas.

Procesamiento de datos

El procesamiento de datos convierte los datos brutos en información útil.

1. Recolección  →  Captura de datos desde diversas fuentes.
2. Organización →  Clasificación y estructuración de los datos.
3. Análisis     →  Interpretación para extraer patrones.
4. Presentación →  Visualización de resultados (informes, gráficos).

Información

La información son datos que han sido organizados, procesados y presentados en un contexto que les da significado y utilidad para la toma de decisiones.
10 / PROCESOS

Procesos

Un proceso es una serie de pasos o actividades organizadas para concebir, diseñar, construir, probar y mantener un producto de software.

Características de los procesos

Organizados

Siguen una secuencia lógica.

Repetibles

Pueden ejecutarse múltiples veces con resultados consistentes.

Medibles

Permiten evaluar su eficiencia y eficacia.

Mejorables

Pueden optimizarse con retroalimentación.

Procesos en sistemas de información

Los sistemas de información son mecanismos y herramientas que permiten intercambiar información técnica y funcional entre diferentes actores de un proyecto de software y entre componentes o sistemas informáticos.

Característica Descripción
Automatización Reducción de la intervención manual.
Trazabilidad Capacidad de rastrear el flujo de información y cambios.
11 / SISTEMAS

Sistemas de información

Un sistema de información es el conjunto de agentes, códigos y procesos que interactúan coordinadamente entre sí con un fin común o propósito.

Elementos de un sistema de información

Hardware

Dispositivos físicos: computadoras, servidores, dispositivos móviles.

Software

Programas y aplicaciones que procesan la información.

Datos

Hechos y cifras que el sistema gestiona.

Personal

Usuarios, administradores y personal de soporte.

Procesos

Procedimientos y reglas para el manejo de la información.

Redes

Infraestructura de comunicación que conecta los componentes.

Objetivos

  • Gestionar, almacenar y proveer datos e informaciones.
  • Apoyar la toma de decisiones en la organización.
  • Automatizar y optimizar procesos de negocio.

Clasificación

Tipo Función
Sistemas transaccionales Procesan operaciones básicas (ventas, nómina, inventario).
Sistemas de apoyo a decisiones Ayudan en la toma de decisiones gerenciales.
Sistemas estratégicos Apoyan la ventaja competitiva de la organización.
12 / SDLC

Ciclo de vida del software

El ciclo de vida del software (SDLC) es un proceso que abarca desde la planificación inicial hasta la implementación y mantenimiento del software. Divide el desarrollo en fases diferenciadas, repetibles e interdependientes, cada una con sus propios objetivos y tareas.

Fases del ciclo de vida

Fase Descripción
PlanificaciónDefinición del alcance, objetivos y recursos del proyecto.
AnálisisRecolección y análisis de requisitos del cliente.
DiseñoEspecificación de la arquitectura y componentes del software.
DesarrolloCodificación y construcción del software.
PruebasVerificación y validación del software.
DespliegueInstalación y puesta en producción del software.
MantenimientoCorrección de errores y actualizaciones posteriores.
Nota: la escalabilidad es un aspecto que se mejora a medida que el sistema evoluciona en el tiempo.

Modelos de ciclo de vida

Modelo Descripción
Waterfall (Cascada)Modelo secuencial y lineal.
IncrementalDesarrollo por partes, entregando funcionalidades gradualmente.
EspiralCombina desarrollo iterativo con análisis de riesgos.
V-ModelVerificación y validación en cada fase.
ÁgilDesarrollo iterativo y colaborativo (Scrum, XP, etc.).
RADDesarrollo rápido con prototipos.
El cómo se trabaja entre los grupos desarrolladores para crear un sistema.
13 / METODOLOGÍAS

Metodologías de desarrollo

Una metodología de desarrollo de software es el conjunto de técnicas y métodos organizativos que se utilizan para diseñar, planificar y controlar el proceso de construcción de una solución de software.

Tipos de metodologías

Tradicionales

Enfoque predictivo, planificación detallada, procesos secuenciales (ej. Cascada).

Ágiles

Enfoque adaptativo, iterativo, colaborativo y flexible (Scrum, XP, Lean).

14 / SCRUM

Metodología Scrum

Scrum es un marco de trabajo ágil que organiza proyectos complejos en ciclos cortos llamados sprints. Se basa en la definición de roles, artefactos y ceremonias para lograr una gestión flexible y eficiente del desarrollo de software.

Roles en Scrum

Product Owner

Define y prioriza las funcionalidades del producto.

Scrum Master

Facilita el proceso y elimina impedimentos.

Equipo de Desarrollo

Equipo autoorganizado que construye el producto.

Artefactos en Scrum

Artefacto Descripción
Product BacklogLista priorizada de requisitos del producto.
Sprint BacklogTareas seleccionadas para un sprint.
IncrementoResultado del sprint, una versión funcional del producto.

Eventos o ceremonias

Evento Propósito
Sprint PlanningPlanificación del sprint.
Daily ScrumReunión diaria de sincronización.
Sprint ReviewRevisión del trabajo completado.
Sprint RetrospectiveReflexión para mejorar el proceso.
15 / APLICACIÓN

Aplicación en el desarrollo de software

"En desarrollo de software, pensar en sistemas es la diferencia entre código que funciona y arquitecturas que perduran."

La TGS ofrece una visión integral que permite:

Arquitecturas robustas

Diseñar arquitecturas de software robustas y escalables.

Interacciones

Entender las interacciones entre módulos, bases de datos, redes y usuarios.

Anticipar fallos

Anticipar comportamientos emergentes y puntos de fallo.

Comunicación

Mejorar la comunicación entre equipos multidisciplinarios.

El conocimiento de los sistemas de información, el ciclo de vida del software y las metodologías de desarrollo (especialmente las ágiles como Scrum) es fundamental para caracterizar procesos, recolectar información y establecer requisitos de acuerdo con las necesidades del cliente.
