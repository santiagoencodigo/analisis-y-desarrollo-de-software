Metodología Tradicional

Proceso Unificado
Racional (RUP)

Un proceso de desarrollo de software iterativo e incremental, basado en el modelo en cascada y guiado por casos de uso. Se centra en la arquitectura del sistema y en la documentación exhaustiva.

01 / INTRODUCCIÓN

Introducción a RUP

El Proceso Racional Unificado (RUP) es un marco de trabajo de desarrollo de software que proporciona un enfoque disciplinado para asignar tareas y responsabilidades. Su objetivo es garantizar la producción de software de alta calidad dentro de un presupuesto y cronograma predecibles.

Los 3 pilares de RUP:
  • Dirigido por casos de uso: Guían todo el proceso, desde los requisitos hasta las pruebas.
  • Centrado en la arquitectura: El eje sobre el que se construye el software.
  • Iterativo e incremental: Ciclos que producen incrementos funcionales.
02 / CARACTERÍSTICAS

Características Principales

RUP se considera una metodología tradicional o "pesada" debido a su énfasis en la documentación y planificación.

Característica Descripción
Documentación extensiva Cada fase genera artefactos documentados como base para las siguientes etapas.
Planificación rigurosa El plan de proyecto se define en las fases iniciales y se refina iterativamente.
Flexibilidad limitada Los cambios son costosos, especialmente en etapas avanzadas.
Roles definidos Asigna responsabilidades claras a cada perfil dentro del equipo.
03 / CICLO DE VIDA

Fases de RUP

3.1 Incepción (Inicio)

Objetivo: Establecer la viabilidad y delimitar el alcance.

Actividades: Definir el ámbito, identificar casos de uso críticos, evaluar riesgos, estimar costos.

Artefactos: Documento de requerimientos, boceto de arquitectura, plan preliminar.

3.2 Elaboración

Objetivo: Sentar las bases arquitectónicas.

Actividades: Refinar casos de uso (80%), construir prototipo arquitectural, mitigar riesgos.

Artefactos: Prototipo ejecutable, casos de prueba iniciales, plan detallado.

3.3 Construcción

Objetivo: Desarrollar el código fuente completo.

Actividades: Análisis, diseño, implementación y pruebas de iteraciones. Documentación del sistema.

Artefactos: Software completo, casos de prueba actualizados, manuales de usuario.

3.4 Transición

Objetivo: Entregar el producto a los usuarios finales.

Actividades: Liberar el producto, entrenamiento, soporte, ajustes finales.

Criterio: Usuario satisfecho y objetivos de Incepción alcanzados.

05 / EQUIPO

Roles en RUP

Categoría Roles
Analistas Analistas de procesos, diseñadores del negocio, analistas del sistema, especificadores de requisitos.
Desarrolladores Arquitectos de software, diseñadores de BD, desarrolladores backend/frontend, integradores.
Probadores Diseñadores de pruebas, implementadores de pruebas.
Otros Artistas gráficos, administradores de sistemas, especialistas en herramientas, gestores de configuración.
06 / BALANCE

Ventajas y Desventajas

Ventajas
  • Proporciona un marco estructurado y disciplinado.
  • Genera documentación completa que facilita el mantenimiento.
  • Permite una planificación detallada y control de costos.
  • Es escalable para proyectos grandes y complejos.
Desventajas
  • Puede ser demasiado pesado y burocrático para proyectos pequeños.
  • La rigidez dificulta la adaptación a cambios frecuentes.
  • Requiere una inversión inicial significativa en análisis y diseño.
  • La curva de aprendizaje es alta para equipos sin experiencia.
